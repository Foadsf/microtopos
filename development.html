Run and test from source

git clone https://github.com/Foadsf/microtopos.git
cd microtopos
uv run microtopos --simulator           # the application on the synthetic specimen
uv run microtopos-selftest              # ground-truth self-test, 3 seeds (about 5 minutes)
uv run microtopos-selftest --quick --gui  # one seed plus an offscreen GUI run
uv run --group dev pytest               # the same checks as unit tests

microtopos-record OUTDIR records raw MJPEG frames from the camera for offline work, and --replay OUTDIR plays them back through the full live pipeline. microtopos-selftest --real OUTDIR adds checks on a recording of a lit specimen.

Architecture

Module Responsibility

camera

capture threads (V4L2/OpenCV, latest-frame pull, reconnect), camera controls, simulator and replay sources (real-time, or ordered with back-pressure)

recording

one recording writer for the GUI and microtopos-record (MJPEG bytes or lossless PNG, checked writes, a manifest kept current) and the validated manifest reader

batch

deterministic offline reconstruction of a whole recording (microtopos-batch)

backend

optional OpenCL focus measure with the CPU as reference, parity checks and the benchmark (microtopos-bench)

units, verdict

canonical unit ids; typed self-test verdicts shared by the CLI, pytest and the JSON log

kinematics

motion state machine: DWELL, PAN, Z_SWEEP, OBJECTIVE_CHANGE, from noise-normalised video features with hysteresis

live

the engine thread: state, sweep capture with source sequence numbers and times, completeness, pre-roll, mosaic updates, source and mosaic generations, snapshots for the GUI

mosaic

band-pass phase correlation refined by ECC, NCC verification, keyframe pose graph with loop closure, relocalisation, height patches

registration, focus, sff, zstack

sweep registration, focus measures, depth fitting and refinement, all-in-focus fusion, the reconstruction pipeline

metrology, export

ISO 25178-style parameters, filters and grains; GSF, TIFF, STL, report bundle and sessions

optics, calibration, simulator

objective model, calibration store and radiometric correction, synthetic specimen renderer

objectives

the user’s objective list (objectives.json): presets, validation, the one name→optics resolver (also for objectives no longer in the list), edits that carry calibrations across renames

gui

the Qt (PySide6) window, built on pyqtgraph

Reading the live state never blocks: the engine publishes an immutable snapshot after each frame and the GUI draws the latest one. Controls that change the engine (source, objective, mode, mosaic reset) take its lock briefly; mosaic rendering happens outside that lock, at display size. Reconstruction, metrology recomputation, rescaling and super-resolution run as jobs that the window owns. Closing the window cancels them and waits until they have stopped. One bad frame does not stop the engine: the error is counted, logged and shown.

Measurement identity

Every sweep carries the source id and generation, the mosaic generation, the objective, the calibration revision and the source sequence number and time of each frame. A finished height map is pinned only into the mosaic it was captured in. A calibration is written to the result’s own objective. Dark and flat averages are cancelled if the source, size, exposure, gamma setting or objective changes before they are complete. Results compare (repeatability) or blend (mosaic) only when their height quantity agrees: same unit, a known sign, and the same scale basis.

Verification

The self-test renders a synthetic specimen with the same optics model the measurement relies on. Every instrument parameter is randomised per seed. It checks the pipeline against the known truth: 130 checks pass, 0 fail, and 30 are informational (measured 2026-11-05 on an i5-8365U laptop). The signed-step check uses a blur law that is independent of the optics model. --json FILE records every row, the thresholds and the versions.

The gate itself is tested. Every verdict goes through one normalisation, so a NumPy False counts as a failure. A non-boolean verdict, an exception or an empty check is an error. The totals and the exit code come from the same records. A subprocess test makes sure an injected failing row exits 1.

pytest adds 83 tests, among them recording, replay, engine-error, calibration-ownership, objective-list (persistence, validation, old sessions, calibrations across edits, presets), late-result, export and session tests, and a check that two batch runs of the same recording give identical results.

On real camera data (Bresser MikrOkular Full HD on a metallurgical sample): stitching along a known path tracked 40/40 frames at 0.21 px RMS. Depth over a known synthetic relief, with real texture blurred by the optical model, gave r 0.986, slope 0.993 and RMSE 0.91 µm (0.09 DOF). A 3-minute still recording of 2,236 frames produced no false detections.

Important
 Real-sample accuracy against a certified roughness or step-height standard has not been measured yet. Contributions of such measurements are very welcome.

Compute backends

The CPU is the reference and the default. ZSettings.backend = "opencl" runs the DoG focus measure through OpenCV’s OpenCL path, falls back to the CPU on any error, and the result records which backend ran. microtopos-bench measures both, synchronised and after warm-up, with a parity check and a negative control. On the development laptop (Intel UHD 620): relative L2 difference 1.1e-7, 3.4 ms with transfers against 3.6 ms on the CPU for one 960×540 frame. That is too small a gain to change the default; a GPU backend has to show an end-to-end improvement first.

Builds and releases

packaging/build.py builds a single-file executable with PyInstaller. Pushing a tag v* runs the release workflow:

  • builds for Linux x86-64 (on Ubuntu 22.04, for the oldest glibc) and ARM64, Windows x86-64, and macOS ARM64 and x86-64;

  • runs --selftest --quick --gui --json with each built program on its runner (on macOS, the app extracted from the published zip), and attaches each runner’s JSON rows to the release;

  • publishes the files with SHA256SUMS.txt. PyInstaller is pinned to an exact version.

Linux builds deliberately leave out the system’s graphics, X11, font and C++ runtime libraries, so the program uses the user’s own drivers.

This website

The site is written in AsciiDoc (docs/pages/*.adoc) and built with Asciidoctor.js into one shared template (docs/build.mjs, docs/assets/). The screenshots are taken from the real application running on the simulator, so they can be regenerated after any GUI change:

uv run python docs/tools/screenshots.py                    # all shots, offscreen
uv run python docs/tools/screenshots.py --platform xcb --only tab-3d   # 3D needs a real display
cd docs && npm ci && npm run build                         # -> docs/_site

A workflow builds the site on every push to main that changes docs/ and publishes it on the gh-pages branch.

Contributing

Bug reports with a raw recording are the most useful contribution: they replay exactly. For code, run the self-test and pytest before a pull request, and keep the numbers honest: a claim in the README or here needs a check that measures it.
